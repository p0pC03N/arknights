# 缺页相关基础补充

```text
compose.yaml / Dockerfile / run.sh
        ↓
启动 qemu / docker 环境
        ↓
bzImage           Linux 内核镜像
        ↓
initramfs.cpio.gz 初始根文件系统
        ↓
init / linuxrc    启动脚本或启动程序
        ↓
driver.ko         内核模块
```

```text
程序使用的虚拟地址
        ↓
      页表
        ↓
真实内存条上的物理地址
```

```text
用户程序 / 内核代码
        │
        │ 访问一个虚拟地址
        ▼
      CPU/MMU
        │
        │ 查页表
        ▼
    找到物理地址
        │
        ▼
    访问真实内存
```

## PTE (Page Table Entry)

页表是一张表，PTE 就是表里的一行。

+ PTE 高位：物理页地址
+ PTE 低位：权限/状态

例如：

```text
PTE = 0x0000000012345067

0x12345000  是物理页地址
0x067       是 flags
```

常见 flags：

| 位 | 含义 |
| --- | --- |
| Present | 这一页是否存在 |
| Writable | 是否可写 |
| User | 用户态是否可访问 |
| NX | 是否禁止执行 |

```text
Present = 1：这页现在有效
Present = 0：这页现在没映射，访问会出问题

Writable = 1：可以写
Writable = 0：不能写

User = 1：用户态可以访问
User = 0：只有内核态能访问

NX = 1：不可执行
NX = 0：可以执行
```

所以如果某页 PTE 的 `Present = 1`、`Writable = 0`、`User = 1`、`NX = 1`，意思就是：用户程序可以读这页，但是不能写，也不能执行。

如果往这页写，就会异常。

## 缺页 (Page Fault)

```text
程序访问地址
    ↓
CPU 查页表
    ↓
发现有问题
    ↓
触发 page fault
    ↓
进入内核的缺页处理函数
```

触发条件：

+ 虚拟地址没映射
+ 暂时未分配
+ 只读页
+ 执行了不可执行页

有时 `malloc` 返回了虚拟地址，但物理页还没真正分配。

第一次访问时：

```text
CPU 查页表：Present = 0
触发缺页
内核发现：这是合法地址，只是还没分配物理页
内核分配一个物理页
修改 PTE
返回用户程序
程序继续执行
```

这就是按需分页，也就是 demand paging。

只读页通常表现为：

```text
Present = 1
Writable = 0
```

不可执行页通常表现为：

```text
NX = 1，但是程序跳过去执行
```

## 页表

页表是多级结构：`PGD → P4D → PUD → PMD → PTE`。很多 4 级页表里，P4D 是折叠的。

```text
a3 = 0x00007ffff7dd0123

        虚拟地址
           │
           ▼
      PGD index
           │
           ▼
        PGD 表
           │
           ▼
      PUD index
           │
           ▼
        PUD 表
           │
           ▼
      PMD index
           │
           ▼
        PMD 表
           │
           ▼
      PTE index
           │
           ▼
        PTE 表
           │
           ▼
        PTE 项
           │
           ▼
      物理页地址
           │
           ▼
  物理页地址 + 页内偏移
```

## 其他概念

walk 页表，就是一层一层查页表。

拿到 PTE 指针之后，就可以看或者改这一页的属性。

```text
程序访问虚拟地址 a3
        ↓
CPU 查页表
        ↓
找到 a3 所在虚拟页的 PTE
        ↓
PTE 告诉 CPU 对应物理页和权限
        ↓
权限允许：访问真实物理内存
权限不允许/不存在：触发缺页异常
        ↓
内核处理缺页
```

+ `invlpg` (INValidate TLB entry for a PaGe)：让 CPU 忘掉某个虚拟地址对应的 TLB 缓存，使得修改后的 PTE 能立即生效。
+ `copy_from_user()`：从用户态内存拷贝数据到内核态内存。
+ `PFN` (Page Frame Number)：物理地址 / 页大小。
